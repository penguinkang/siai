# Proposer API

Import these objects from `siai`.

## `ModelCard`

```python
ModelCard(
    objective: str,
    metric: str,
    direction: str,
    levers: dict[str, str],
    constraints: tuple[str, ...] = (),
    guardrails: tuple[MetricGuardrail, ...] = (),
)
```

`direction` is `"maximize"` or `"minimize"`. At least one lever is required.
Lever descriptions and constraints guide the proposer; the trainer must enforce
them.

## `MetricGuardrail`

```python
MetricGuardrail(
    metric: str,
    direction: str,
    threshold: float,
)
```

`direction` is `"at_least"` or `"at_most"`; thresholds must be finite. Guardrail
metric names must be unique within a model card. `passes(value)` applies the
inclusive threshold.

## `Observation`

```python
Observation(
    id: str,
    kind: str,
    summary: str,
    value: float | None = None,
    artifact: str | None = None,
)
```

Identified search-time evidence. Numeric values must be finite. An artifact is an
opaque reference and is not fetched by SIAI.

## `ProposalRequest`

```python
ProposalRequest(
    card: ModelCard,
    incumbent: Candidate,
    observations: tuple[Observation, ...],
    history: tuple[dict, ...] = (),
    remaining_evaluations: int = 1,
)
```

The complete input contract for an intelligent proposer.

## `Proposal`

```python
Proposal(
    lever: str,
    value: object,
    hypothesis: str,
    evidence_ids: tuple[str, ...],
    expected_effect: str,
    verification: str,
    provider: dict | None = None,
)
```

`candidate(incumbent)` returns a new `Candidate` by replacing the selected
top-level lever while preserving all other configuration values.
`provider` contains optional call metadata added by the provider adapter; it is
not generated by the model and does not affect the candidate.

## `IntelligentProposer`

```python
IntelligentProposer(generate, *, max_observations: int = 64)
```

`generate(prompt: str) -> str` supplies a provider-specific model call. Calling
`propose(request)` makes exactly one call and returns a validated `Proposal`.
It raises `ValueError` for exhausted budget, duplicate observation IDs, malformed
JSON contracts, unknown levers, invented evidence IDs, and repeated candidates.

`max_observations` bounds the current evidence included in the provider prompt.
Failures, objective-related metrics, slices, and training signals are ordered
before routine cost signals. All observations remain in the caller's immutable
`ProposalRequest`.

## `build_proposal_context`

```python
build_proposal_context(
    request: ProposalRequest,
    *,
    max_observations: int = 64,
) -> dict
```

Returns the exact trainer-neutral decision packet used by
`IntelligentProposer`. Prior journal rows are reduced to candidate, parent,
configuration, lever, value, hypothesis, score, directional gain, named metrics, guardrail
status, acceptance, and errors.
`directional_gain` is normalized so positive always means improvement.
